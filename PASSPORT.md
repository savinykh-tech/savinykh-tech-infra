# ПАСПОРТ ИНФРАСТРУКТУРЫ И НАВЫКОВ

## 1. Спецификация Сервера (Hardware & OS)

- **Хост-провайдер:** Aeza VPS
- **Тарифный план:** HELs-1 (Локация: Хельсинки, Финляндия)
- **Операционная система:** Ubuntu 24.04.1 LTS
- **Сетевое ядро:** Алгоритм BBR (TCP Congestion Control) активирован для оптимизации сетевого трафика.
- **Ресурсы:**
  - CPU: 1 Core
  - RAM: 2.0 GB
  - SWAP: 2.0 GB (Подключен в качестве подушки безопасности от OOM-killer при пиковых нагрузках n8n/Caddy)
  - Накопитель: 30 GB NVMe (~18 GB свободно после очистки 13 GB логов AdGuard Home)

## 2. Сетевая Архитектура и Безопасность

- **Периметр хоста (UFW):** Strict-политика. Открыты только порты:
  - `4422` (Кастомный защищенный порт SSH)
  - `80` / `443` (Caddy Веб-трафик / DoH)
  - `853` (AdGuard Home DNS-over-TLS)
  - `2053`, `2083`, `8443` (Панель 3x-ui / Xray)
- **Порт 53 (Стандартный DNS):** Полностью закрыт снаружи для предотвращения DNS-amplification атак и сканирования.
- **Доступ на сервер:** Исключительно по аппаратному SSH-ключу (алгоритм `ed25519`). Аутентификация по паролю оставлена только как аварийный бэкап через VNC-панель Aeza. Приватный ключ зашифрован и сохранен на внешнем отказоустойчивом хранилище.
- **Защита от брутфорса:** Активен `Fail2Ban`, изолирующий подозрительные IP-адреса на уровне iptables.
- **Маршрутизация DNS:**
  - Основной контур мобильных устройств и домашнего роутера MikroTek переведен на приватный DNS-over-HTTPS (`https://savinykh-tech.ru/dns-query`) через собственный апстрим AdGuard Home.
  - Резервный контур: Cloudflare DNS (`1.1.1.1`).

## 3. Контейнеризация и Сервисы (Docker Environment)

Управление контуром осуществляется через Docker Compose. Локальный веб-интерфейс менеджмента — Portainer (`https://savinykh-tech.ru/manage`).

| Название контейнера | Порт (Внутренний -> Внешний)                 | Статус  | Роль в архитектуре                                         |
| :------------------ | :------------------------------------------- | :------ | :--------------------------------------------------------- |
| **caddy**           | `80:80`, `443:443`                           | Running | Реверс-прокси, автоматический SSL (Let's Encrypt), TLS 1.3 |
| **n8n**             | `3000 -> proxy`                              | Running | Ядро автоматизации (интеграция API, парсеры). БД: SQLite   |
| **adguardhome**     | `853:853` (DoT), `443:443` (через Caddy DoH) | Running | Фильтрация рекламы, трекеров и локальный DNS-сервер        |
| **3x-ui (Xray)**    | `2053`, `2083`, `8443`                       | Running | Безопасный прокси-туннель                                  |
| **jarvis (Flask)**  | `5000` (Внутренняя сеть Docker)              | Running | Бекенд-бот для обработки лидов с лендинга                  |
| **watchtower**      | `-`                                          | Running | Автоматическое обновление образов контейнеров              |

### Специфика конфигурации контейнера n8n (Bind Mounts):

1. Папка `/home/jarvis_admin` примонтирована в контейнер как `/host` для прямого сохранения файлов бэкапов.
2. Бинарный файл `/usr/bin/curl` проброшен внутрь контейнера в режиме _Read-Only_ для реализации автономной отправки уведомлений и архивов в Telegram через ноду `Execute Command`.

## 4. Стратегия Хранения Данных и Секретов

- **Политика Zero-Hardcode:** Любые авторизационные токены, пароли, логины API и ключи сессий полностью удалены из переменных окружения Docker, конфигурационных файлов `docker-compose.yaml` и `Caddyfile`.
- **Хранилище секретов:** Все чувствительные данные перенесены в изолированное и зашифрованное внутреннее хранилище `n8n Credentials`.
- **Резервное копирование:**
  - Локальный контур: Скрипт `~/save.sh` собирает конфигурационные файлы сервисов в директорию `~/backups/`.
  - Удаленный контур: Воркфлоу n8n по расписанию архивирует локальные бэкапы и отправляет их в защищенный Telegram-канал через Curl.
